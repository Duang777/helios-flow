# 经营闭环本地体验测试清单

给操作者按模块逐项勾选。目标：确认页面有数、中文可读、经营 AI 能答、写入只走确认卡。


| 项    | 值                                                                               |
| ---- | ------------------------------------------------------------------------------- |
| 环境   | 本地 `http://localhost:3000`                                                      |
| 账号   | `admin@helios.com` / `secret`                                                   |
| 组织   | 北京四维图新科技股份有限公司                                                                  |
| AI   | `insights.operating_loop_assistant` + `deepseek-v4-flash`（`HELIOS_AI_BASE_URL`） |
| 文档用途 | 人工体验，不是自动化脚本                                                                    |


## 统一判定标准

每道题通过需同时满足：

1. **有数或明确空结果**（条数 / 金额 / `0` 均可）
2. **有证据**：`证据:` / ID / 来源表或工具名
3. **有后台链接**：含 `/backend/...`（优先 Markdown：`[可读名称](/backend/...)`，不要只贴裸路径）
4. **写入场景**：出现确认卡，或明确说「需确认 / 未写入」；**不得**说已经写入成功
5. **中文**：标题、按钮、AI 回复主体可读，无明显乱码

通用操作：

1. 打开页面 → 看列表/卡片是否有内容
2. 点 **「问摘要」** 或行上 / 页头的 **经营助手 / AI**
3. 粘贴本文「测试提问」→ 对照「通过标准」勾选

## 1. 今日经营摘要（入口）


|      |                                                                                                                            |
| ---- | -------------------------------------------------------------------------------------------------------------------------- |
| 路径   | [http://localhost:3000/backend/insights/operating-loop/today](http://localhost:3000/backend/insights/operating-loop/today) |
| 你该看到 | 严重检出 / 逾期应收 / 延期项目 / KPI 缺口 四张卡                                                                                            |




### 测试

- [ ] **T1.1 页面有数**  
  卡片至少有数字（可为 0）。严重检出口径与治理列表一致：当前组织 **open + critical**（不要求 exact asOf）。当前演示环境常见：逾期应收、延期项目、KPI 缺口 > 0。

- [ ] **T1.2 问摘要**  
  点「问摘要」，提问：
  ```text
  今天最该先处理什么？请按 critical 检出、逾期回款、延期项目、KPI 缺口排序，给数字、证据和后台链接。回答里出现「今日」或「今天」。
  ```
  通过：四类都提到；有链接；未声称已写入。

## 明确不要测 / 不要做的事

- 不要在生产或公网未加固环境打开 `HELIOS_AUTOLOGIN_*`
- 不要让 AI 在无人确认时收货 / 调拨库存 / 改集成凭据 / 启停危险工作流定义
- 确认卡场景以「出现卡片」为准即可，演示时可一律取消，避免脏数据
- API Key 不要贴进截图或提交到 git
